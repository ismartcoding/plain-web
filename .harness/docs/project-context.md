# Project Context

> Living document. Keep it short. Pointers to `docs/`, not summaries of them.

## What this repo is

`plain-web` is the web/desktop UI for the PlainApp project (`plainhub/plain-app` on GitHub). It is **not** a standalone app — it is the *client* half of a paired system:

- **Server half**: `plain-app` (Kotlin/Android). Owns the phone, the SQLite DB, the TLS endpoints, the broadcast channels.
- **Client half**: this repo. Vue 3 SPA that talks to the server over GraphQL/HTTPS, plus a Tauri 2 desktop shell that embeds a local GraphQL server (Rust) for offline / peer-to-peer scenarios.

When a task says "align with plain-app", it means **make the Rust code in `src-tauri/src/local/` produce the same wire behavior as the Kotlin server**. The user maintains the Kotlin reference; we mirror it.

## Stack split

| Layer | Code | Stack |
|---|---|---|
| UI | `src/` | Vue 3.5 + Composition API, Pinia 3, Apollo Client, vue-i18n, SCSS, Vue Router, CodeMirror 6 |
| Web build | `vite.config.ts` | Vite 5.4, Yarn 4 (Corepack), TypeScript 5.8 |
| Desktop shell | `src-tauri/` (top-level) | Tauri 2 + plugins (store, notification, opener, log) |
| Local server / DB | `src-tauri/src/local/` | async-graphql 7, rusqlite (bundled), XChaCha20-Poly1305, ECDH P-256, Ed25519 |
| Tauri commands | `src-tauri/src/commands/` | Window mgmt, macOS menu/dock, WS proxy, HTTP client, notifications |
| Tests | `tests/lib/` | Vitest + happy-dom (unit only) |

## Active work area: chat

- **Status**: in flight. Plan: `docs/chat-plain-app-alignment-plan.md`. Open follow-up: `docs/chat-local-mode-upload-fix.md`.
- **Why it matters**: the chat block is the only place the local server has to *re-implement* server logic (since the phone may be offline). Every other block proxies to the real `plain-app` server.
- **Rule of thumb**: when in doubt about wire format, event names, or DB column semantics, read the matching Kotlin schema first (`plain-app/.../web/schemas/*.kt` or `plain-app/shared/.../db/*.kt`) — never the other way around.

## What's NOT here

- No CI for tests or lint. `.github/workflows/release.yml` is **release-only** (manual `workflow_dispatch`). Verification is local + on-PR.
- No Storybook, no Playwright, no E2E. UI verification is manual on the dev server.
- No translation memory. i18n is en-US authored; other locales are auto-generated by Crowdin.

## Conventions that bite if missed

- **Resolver file routing** (`src-tauri/src/local/graphql/schema/`): `chat_query.rs` for queries, `chat_message.rs` for message mutations, `chat_channel.rs` for channel mutations, `chat_member.rs` for member mutations. Keep them split — the plan and the Kotlin reference both rely on this split.
- **async-graphql naming**: `snake_case` field names; the framework converts to `camelCase` over the wire. Do not add `#[graphql(name = "…")]` to match Android spelling.
- **`to_id` / `peer:` / `channel:` prefixes** on message fields are part of the protocol. Stable.
- **Vue `V` prefix** for base components in `src/components/base/` (VModal, VTextField, …). New base components must follow the prefix; feature components do not.
- **No comments in new code**. See `.trae/rules/project_rules.md` for the full list.
